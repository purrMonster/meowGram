decision: One transaction stores the message and exact 201 JSON response under
(sender_kind, sender_id, opaque key). A PostgreSQL advisory transaction lock
serializes duplicates across processes. SHA-256 fingerprints decoded text before
trimming. Changed text returns 409; replay authenticates again, consumes API
budget, but does not write/publish or consume a second message-write allowance.

decision: Additive repeatable migration 000006, non-destructive down. Retention
is configurable from 168h to 8760h, default 168h. Expired keys may be replaced
atomically when reused; old messages are never deleted. Unused expired key rows
remain until a separately reviewed cleanup policy; expiry ends the replay promise,
not the message's lifetime. No deletion of messages or profile backfill.

decision: POST send supports human OIDC and optional bot Basic, default off.
GET bot sync remains UST-2.4.3. The old startup prohibition is replaced by actual
send-route wiring and fail-closed directory construction. No live activation.
Reader/LDAPS/group/trusted-proxy policy is unchanged. Disabling Basic leaves human
send available. Bots cannot access other routes via the send gate.

Config for runbook fold:
- MESSAGE_SEND_ENDPOINT: /api/messages, exact path; reserved routes rejected.
- IDEMPOTENCY_RETENTION: 168h default, range 168h–8760h.
- API_RATE_PER_MINUTE must be >=30 and GLOBAL_RATE_PER_MINUTE >=60 when Basic
  is enabled (defaults 120 and 6000); human-only settings retain existing range.
- CORS permits Idempotency-Key, with existing origin restrictions unchanged.
- The shared message budget now namespaces human and bot IDs on both HTTP and
  WebSocket paths. The existing limiter test fixture was updated to the human
  namespace, retaining its rejection-before-database assertion.

Durability: a committed response remains 201 if the hub has stopped. A crash
between commit and publication can omit live delivery; sync recovers it. Replays
never republish, preserving at-most-once publication and push triggering. No
claim of exactly-once network delivery. Responses and raw credentials are not logged.
