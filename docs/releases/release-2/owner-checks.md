# Release 2 owner checks

These checks require live systems or physical devices and were not run by the agent. Scratch-provider and container evidence is recorded separately in each story log. Do not enable Basic until the message API integration is merged.

1. **LLDAP reader and transport (10 minutes, rollout only).** On the authorized deployment host, verify the configured directory namespace is stable, the LDAPS certificate matches the configured hostname, and the least-privilege reader can read entryUUID, cn and direct memberOf under the configured people base. Store any approved reader credential only in the host-local ignored secret file. Expected: verified TLS succeeds; wrong CA and a nonmember bot are denied; group removal is visible on the next request.
2. **HTTPS proxy boundary (10 minutes, rollout only).** Verify only the intended proxy can reach the backend, published ports remain loopback-bound, plaintext ingress is rejected, and the proxy overwrites X-Forwarded-Proto. Configure only the proxy's actual peer CIDRs. Expected: a spoofed forwarded header from another peer cannot authorize Basic requests.
3. **Client/device rollout (15 minutes per platform).** After deployment is separately authorized, sign in with a human account, view old/new history and a distinctly labelled bot message, reconnect and confirm no duplicate rows. On a supported physical device verify the existing push notification path. Expected: human login and chat work; bot labels do not become self messages; provider delivery is confirmed on-device. Native packaging/live provider delivery are not established by container web tests.
